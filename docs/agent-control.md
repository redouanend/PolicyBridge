# Agent control

**Le document d'instruction (scope-confirmation).** Ce document devait se déclencher avant qu'une session n'élargisse le scope d'un ticket ou d'une revue de code sans demander confirmation, un comportement observé lors du Lab 1 (bundling non sollicité de 4 tickets dans un seul commit). Testé sur 3 tâches distinctes (revue ouverte de experts.html, tentative de correction de bug, revue de data.js), le pointeur n'a jamais été consulté par l'agent, malgré un texte retravaillé une fois pour élargir son champ de déclenchement. Le bon comportement final observé au 3ème test provenait en réalité d'une mémoire distincte, pas de cette skill. Un cas où il ne devrait pas se déclencher : une tâche mono-sujet explicitement bornée par l'utilisateur (par exemple "renomme ce bouton"), où il n'y a rien à élargir.

**L'enforcement (hook de confirmation de commit).** Un hook PreToolUse intercepte toute commande Bash contenant "git commit" et force une décision "ask" native du CLI avant de laisser passer, quel que soit le contenu exact de la commande, sans jamais chercher de flag ou de fichier d'approbation (ceux-ci seraient reproductibles par l'agent lui-même, qui partage le même shell). L'instruction seule était insuffisante ici parce que la règle ("jamais committer sans validation") doit tenir même dans le dixième cas où l'agent se tromperait par non-déterminisme, un document, aussi bien écrit, reste un jugement sémantique de l'agent, jamais garanti, comme le prouve justement l'échec du document ci-dessus.
